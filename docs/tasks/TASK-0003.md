# TASK-0003: APK Android con Capacitor y reproducción en segundo plano

## Status
IN PROGRESS

## Objective
Empaquetar la aplicación React existente como APK Android mediante Capacitor, manteniendo la PWA Web funcional y reduciendo las interrupciones de reproducción cuando la pantalla se apaga o la app queda en segundo plano. La APK debe conservar el ecualizador DSP y el volumen superior al 100 %.

## Profile and Risk
- Perfil solicitado por el usuario: integración nativa directa, sin reescribir la aplicación.
- Riesgo: medio. Añade una plataforma Android, permisos de batería, notificaciones y un servicio en primer plano.
- Causa raíz conocida: Android/Chrome suspenden el WebView y el `AudioContext` en segundo plano. Un servicio en primer plano y un wake lock reducen el riesgo, pero el comportamiento final depende del fabricante.

## Scope
- Instalar `@capacitor/core`, `@capacitor/cli` y `@capacitor/android`.
- Configurar `appId` `com.diaz.music`, `appName` `Diaz Music` y `webDir` `dist`.
- Añadir permisos de Internet, wake lock, foreground service, media playback, exclusión de batería y notificaciones.
- Declarar `AudioForegroundService` con `foregroundServiceType="mediaPlayback"`.
- Reanudar timers del WebView y adquirir un `PARTIAL_WAKE_LOCK` al pasar a segundo plano.
- Solicitar exclusión de optimización de batería al iniciar.
- Mantener la URL del backend en `localStorage` y pedirla en la APK cuando no esté configurada.
- Permitir CORS desde `https://localhost` y `capacitor://localhost` en `server.py`.
- Añadir scripts `cap:sync`, `cap:open` y `apk:debug`.
- No modificar la lógica de reproducción de la PWA móvil: sigue usando audio directo sin Web Audio.

## Out of Scope
- Publicar en Google Play ni firmar una build de producción.
- Sustituir el reproductor Web por un reproductor nativo (Media3/ExoPlayer).
- Garantizar continuidad en todos los fabricantes o vencer políticas de ahorro de energía no documentadas.
- Cambiar proveedores de música, almacenamiento, Telegram o la API pública.

## Acceptance Criteria
1. `npm run build` compila TypeScript y Vite sin errores.
2. `npm run apk:debug` genera un APK instalable en `android/app/build/outputs/apk/debug/app-debug.apk`.
3. El APK declara `com.diaz.music`, la etiqueta `Diaz Music` y los seis permisos solicitados.
4. El manifiesto final incluye `AudioForegroundService` con tipo `mediaPlayback` y `usesCleartextTraffic="true"`.
5. La PWA sigue cargando en el navegador y no registra errores de ejecución nuevos.
6. En el teléfono, la APK conecta con el backend configurado en el modal y reproduce audio.
7. Prueba física pendiente: dos o más canciones con pantalla apagada, cambio automático, DSP/boost y reanudación tras una pausa prolongada.

## Implementation
- `capacitor.config.ts`: appId, appName, `webDir: 'dist'`, esquema HTTPS, cleartext y mixed content.
- `android/app/src/main/AndroidManifest.xml`: permisos, `largeHeap`, cleartext, actividad y servicio.
- `android/app/src/main/java/com/diaz/music/MainActivity.java`: arranque con `startPath: /index.html` para evitar la URL raíz `https://localhost`, `resumeTimers()`, `webView.onResume()` en `onPause`, wake lock parcial, permiso de notificaciones y solicitud de batería.
- `android/app/src/main/java/com/diaz/music/SafeBridgeWebViewClient.java`: envuelve `BridgeWebViewClient` y captura excepciones de `WebViewLocalServer` para que una petición atípica no cierre la app.
- `android/app/src/main/java/com/diaz/music/AudioForegroundService.java`: canal silencioso de baja importancia, notificación ongoing y `startForeground` con tipo `mediaPlayback`.
- `src/App.tsx`: `IS_NATIVE_APP`, `IS_MOBILE_WEB`, Web Audio habilitado solo en APK, persistencia y normalización de la URL del servidor, modal inicial en nativo.
- `src/main.tsx` e `index.html`: service worker desactivado dentro de Capacitor.
- `server.py`: orígenes CORS de Capacitor.
- `package.json`: dependencias y scripts de sincronización/build.

## Corrección del cierre al configurar la IP (2026-11-10)

- **Reporte del usuario:** la APK se cerró al intentar escribir la IP del servidor.
- **Evidencia:** el diálogo de errores de Android mostró `java.lang.NullPointerException` en `com.getcapacitor.WebViewLocalServer.handleLocalRequest(WebViewLocalServer.java:401)`, en `getLastPathSegment().contains(".")`. Es un fallo conocido de Capacitor 6.2.3 cuando una URL local no tiene último segmento, por ejemplo `https://localhost` sin barra final.
- **Corrección:**
  - `MainActivity` configura `CapConfig` con `startPath: /index.html` para que la carga inicial sea `https://localhost/index.html` y no la raíz vacía.
  - `SafeBridgeWebViewClient` captura cualquier `RuntimeException` del servidor local y devuelve `null` en vez de propagar el cierre.
  - El modal selecciona todo el texto al enfocar el campo y muestra el formato esperado (`192.168.0.36:8000`).
  - La conexión al servidor tiene un retardo de 350 ms para no lanzar una petición por cada tecla.
- **Validación:** build y pruebas JS PASS; APK regenerada. La prueba física en el teléfono sigue pendiente.

## Risks
- El WebView puede seguir siendo suspendido por algunos fabricantes aunque exista un foreground service.
- La solicitud de exclusión de batería se muestra al iniciar y puede ser rechazada; en ese caso el sistema puede cortar la reproducción.
- La APK usa Web Audio para el DSP; si el `AudioContext` se suspende, el audio puede detenerse aunque el proceso siga vivo.
- `usesCleartextTraffic` permite HTTP en la red local; no debe usarse para tráfico en Internet.
- La APK debug no es apta para distribución.
